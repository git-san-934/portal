# nikkei-per(日経平均PER・PBR 買いの合図)

日経平均の PER(株価収益率)で買い時・売り時を判定し、合図のあとの値動きを検証するページです。サーバーは持たない静的サイトです。

## 公開URL

https://git-san-934.github.io/portal/nikkei-per/

## 買いの合図(PER・PBR、売りの合図は出さない)

- PBR(加重平均)が1.2倍を下回ったあと、下から上に1.2倍を抜けた日 → 買いの合図。次の合図は PBR が一度1.3倍を超えてから
- PER(加重平均)が14倍を上から下に割った日 → 買いの合図。次の合図は PER が一度16倍を超えてから
- 売りの合図は2026-11-04にやめた(PER・PBR の売りの線では早く売りすぎることが多く、うまく働かなかったため)
- 買いの合図は `app.js` の `buySignals()` が `analysis.json` の日次データから計算する(合図のあとの成績の表は2026-11-04に削除)
- 過熱のサイン(①の薄いオレンジ): 信用取引の買い残(金額)の1年前からの増え方が、過去3年の中で上位10%に入った週(申込日の5日後から)。`analyze.py` の `heat_report()` が `sentiment.json` から計算する。点灯後1年の上がり方は平均+2.8%(全週は+10.6%)だが、売って買い直すと持ち続けに負けたので、売りの合図にはしていない
- 需給データ: `fetch_sentiment.py` が平日の自動更新のたびに信用残(2002年〜)・裁定残・先物の投資部門別・日経VI を取り、`data/sentiment.json` にためる(JPX には裁定残と先物の投資部門別が直近の数週分しか無いため。たまったら過熱のサインに使えるか確かめる)
- `analyze.py` の `trade_report()`(持つ/現金の交互ルール)と `PATTERNS` は今も計算しているが、ページには出していない

## 参考: PER の水準(判定のルール)

| 判定 | 買い時の検討 | 売り時の検討 | 主に見る期間 |
|---|---|---|---|
| 固定バンド | PER 14倍未満 | PER 16倍超 | 直近10年(今の水準に合わせた線のため) |
| 相対バンド(5年・10年) | その月より前の5年(10年)の月末 PER の平均 −1σ より下 | 平均 +1σ より上 | 全期間 |

- 相対バンドは、時代ごとの PER の水準の違い(バブル期の60倍超、2004年頃の単体→連結の計算変更など)を吸収するためのものです。その月より前の値だけで作るので、先のデータは使っていません
- 理論株価: EPS = 終値 ÷ PER として、EPS × 14倍・EPS × 16倍の線を日経平均に重ねて表示します

## 検証の方法

- 「合図」は線の外に出た最初の日(前に線の外だった日から30日以上空いたら別の合図)
- 合図の日から 1か月(30日)・3か月(91日)・1年(365日)後の終値の変化率の中央値と、当たりの割合(買いは上がった、売りは下がった割合)
- 比べる相手「いつでも」は、同じ期間の毎月末に買った場合。日次と月次が混ざるので月末の1日だけで数えます

## データ

- `data/per_daily.json` — 日次の PER と終値。手で編集しない
  - 取得元は日経平均プロフィル(https://indexes.nikkei.co.jp/nkave/)の月ごとの表(`statistics/dataload?list=per` と `list=daily`)
  - PER は「加重平均」(`weighted`)と「指数ベース」(`index_based`)を列ごとに保存。分析は加重平均を使い、無い日は指数ベース
  - 初回(データが空のとき)は 1986年1月から1か月ずつさかのぼって、取れるだけ取ります
  - 既存データと食い違う値、PER が3〜200倍の外の値は上書きせず、ワークフローを失敗にして知らせます
- `data/per_history_monthly.csv`(任意)— 日次データより前の期間を月次で補うファイル。列は `month,close,per,basis,source`
  (例: `1990-01,37188.95,70.6,単体,出典名`)。日次データがある月より前だけが使われます
- `data/analysis.json` — `scripts/analyze.py` が書く分析結果。ページはこれだけを読みます

## 毎日の更新

`.github/workflows/update-nikkei-per.yml` が平日 17:30・21:00(JST)頃に
`scripts/fetch_per.py` → `scripts/analyze.py` を実行し、変わっていればコミットして GitHub Pages を再デプロイします。
手で動かすときは、ページの「今すぐ更新」から Issue を作る(所有者が作ると `.github/workflows/request-nikkei-per-update.yml` が更新を起動して Issue を閉じる)か、Actions タブ →「日経平均PER更新」→「Run workflow」(`backfill` に `YYYY-MM` を入れるとその月から取り直します)。

## ファイル構成

- `index.html` / `assets/style.css` / `assets/app.js` — ページ本体(portal / nikkei43 と同じデザイントークン)
- `scripts/fetch_per.py` — PER と終値を取得して `data/per_daily.json` に追記(標準ライブラリのみ)
- `scripts/analyze.py` — 判定と検証をして `data/analysis.json` を書く(標準ライブラリのみ)

## 持ち方のくらべ(全部・半分・段階)

同じ PBR・PER の線で、売り買いを「全部」「半分ずつ」「1/3ずつ」「半分だけ売る」「現金の半分だけ買う」「PBR に合わせて毎日調整」「PER だけ」に変えた8通りを `analyze.py` の `PATTERNS` で毎日計算しています(売りの合図をやめたため、ページには出していません)。2004-09〜2026-11 では「全部売り・全部買い」×8.45(買いの線1.1倍) がいちばん良く、半分ずつ ×8.08、PER だけ ×1.81 でした。
