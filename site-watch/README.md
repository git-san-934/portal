# 持ち株サイトの新着ページ

https://git-san-934.github.io/portal/site-watch/

持ち株(日本株)の公式サイト全体を毎日巡回して、前の日までになかったページや PDF を一覧にします。
「持ち株の新着情報」(`news/`)がニュース一覧・適時開示・EDINET を見るのに対して、こちらはサイト全体の URL の増減を見ます
(製品ページ・採用ページ・IR 資料の PDF など、ニュース欄に出ない追加も拾えます)。

## しくみ

1. 各社の `robots.txt` を読み、そこに書かれたサイトマップ(なければ `/sitemap.xml`・`/sitemap_index.xml`)から URL を集める
2. トップページとニュース一覧のページから、同じサイト内のリンクを最大200ページたどって URL を集める(PDF なども拾う)
3. これまでに見つけた URL(`data/seen/<コード>.txt`)と比べて、はじめて見る URL を「新しく見つかったページ」にする
   - リンクだけで見つけた URL は、前回までにも読んだページ(`data/seen/<コード>.pages.txt`)に新しく現れたときだけ載せます。
     1回に読むページ数に上限があるため、日によって奥の過去資料のページまで届くことがあり、そこにある古い PDF を新着と取り違えないためです

- はじめて巡回したサイトは、今の姿を記録するだけで一覧には載せません。次の巡回から、増えたものが載ります
- `robots.txt` で禁止されたページは読みません。同じサイトへは 1.5 秒以上(Crawl-delay があればそれ、最大10秒)あけて読みます
- 画像・CSS・動画などは拾いません。URL の追跡用パラメータ(`utm_*` など)は取り除いて比べます
- 一度に300件を超えて増えたとき(サイトの作り替えなど)は、一覧に300件だけ載せて、巡回の状況に件数を書きます
- サイトに接続できなかった日は記録を変えません(消えたページを「なくなった」とは扱いません)

## 更新のタイミング

`.github/workflows/update-site-watch.yml` が毎日 5:04・8:48・11:50(日本時間)に動きます。GitHub 側の混雑で遅れることがあります。
ページの「今すぐ更新」を押すと、更新依頼の Issue を作る画面が開き、所有者がそのまま作成すると
`.github/workflows/request-site-watch-update.yml` が巡回を起動します(巡回に10〜30分かかります)。
ページ自体は GitHub のキーを持ちません。Actions の画面(「持ち株サイトの新着ページ 更新」→「Run workflow」)から手動でも実行できます。

## 設定

- 銘柄: 「持ち株チェック」の銘柄リスト(`holdings/data/holdings.json`)のうち日本株(`currency` がないもの)
- 公式サイトのURL: 「持ち株の新着情報」と共通(`news/data/sources.json` の `home` と `pages`)
  - どちらにも登録のない銘柄(新しく追加した銘柄など)は、Yahoo Finance の会社情報から公式サイトを探して `data/auto_sites.json` に記録し、そのURLで巡回します。違うサイトが登録されたときは `data/sites.json` に `home` を書くと優先されます
  - 持ち株チェックのページで銘柄リストを保存すると、`apply-holdings-list.yml` がこの巡回も起動します(新しい銘柄はその回でサイトの今の姿を記録し、次の巡回から新着が載ります)
- 銘柄ごとの上書き: `data/sites.json`(`home`・`starts`・`exclude`・`skip`)。英語版のページを外したいとき、巡回しない銘柄を決めるときに使います
  - 任天堂(7974)は、サイトの利用条件でスクレイピングが禁止されているため `skip` にしています(ニュースは「持ち株の新着情報」が RSS で見ています)
  - サイトがアクセスを断る場合(みずほFG は HTTP 403)は、巡回の状況にそう表示し、毎日試し直します

## ファイル

- `scripts/crawl.py` — サイトを巡回して `data/new_pages.json` と `data/seen/` を作る
- `data/new_pages.json` — ページが読むデータ。新しく見つかったページ(直近90日)と各サイトの巡回状況
- `data/seen/<コード>.txt` — これまでに見つけた URL の一覧(1行1つ)。消すと、そのサイトは次の巡回で記録し直します
