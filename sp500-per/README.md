# sp500-per(S&P 500 PER・PBR 買いの合図)

日経平均PER・PBR(`nikkei-per/`)と同じ考え方を S&P 500 に当てはめたページです。サーバーは持たない静的サイトです。

## 公開URL

https://git-san-934.github.io/portal/sp500-per/

## 買いの合図(3種類。売りの合図は出さない)

- ① PER が 20倍を上から下に割った日。次の合図は PER が一度 23倍を超えてから
- ② PER が PER の250日(約1年)移動平均より15%以上低くなった日。次の合図は PER が移動平均の上に戻ってから
- ③ PBR が PBR の500日(約2年)移動平均より5%以上低くなった日。次の合図は PBR が移動平均の上に戻ってから
- ②③は「割高なりに、ふだんより下がった日」を拾うので、①が何年も出ない好調な相場でも出る(2026-11-10 追加)
- 合図と成績は `scripts/analyze.py` が計算して `data/analysis.json` に書く。ページ(`assets/app.js`)は表示するだけ
- 成績: 合図の日から365日後・1095日後の終値の変化率と、その合図が出うる期間(①②は1990年〜、③は2002年〜)のすべての日に買った場合の平均(配当は含めない)
- 移動平均の助走のため、計算は1976年から(①の「23倍を超えてから」の状態も1976年から引き継ぐので、1991-09 の合図は出なくなった)

## 移動平均の合図の決め方(2026-11-10 に検証)

| 試したもの | 結果 |
|---|---|
| PER ÷ PER の移動平均(50〜500日)が −5/−10/−15/−20% を割った日 | −5%・−10%は毎日買うのとほぼ同じ。−15%・−20%は100〜500日のどれでも毎日買うより良い。250日 −15% を採用(2000年以降10回、1年後+12pt、3年後+11pt) |
| PBR ÷ PBR の移動平均 | 500日 −5% が2010年以降12回すべて1年後プラス(2002年以降は18回中16回、2007〜08年の下げ始めで2回はずれ) |
| PER・株価の移動平均のゴールデンクロス | 毎日買うより悪い |
| PER ÷ 250日平均で売り買いを切り替え(買い −15/−10%、売り +5〜+20%) | 2001年から×2.4〜5.9、持ち続け×5.9 にほぼ負ける |

## ① PER 20倍・PBR の水準の線の決め方(2026-11-10 に検証)

日経平均の線(PER 14倍・PBR 1.2倍)は S&P 500 では水準が違いすぎて使えない(2000年以降の中央値: PER 約23倍、PBR 約3倍)。2000-03〜2026-11 の日次データで決め直した。

| 試したもの | 結果 |
|---|---|
| PER 買いの線 17〜24倍 × 準備の線 +2〜4倍 | 17〜21倍ならどれも合図後1年・3年が毎日買った平均を上回る。22倍以上は悪くなる。真ん中の20倍/23倍を採用(2000年以降で6回、1年後・3年後とも6回とも上昇。平均は毎日買うより1年後+10pt、3年後+19pt) |
| 同じルールの1990年代(線を決めるのに使っていない期間) | 1991-09、1994-06 の2回とも1年後・3年後に上昇 |
| PBR 固定の線 2.0〜4.5倍 | 線を少し変えるだけで成績の符号が変わる。2000年のITバブルの4.5倍と、2025年の4.5倍が同じ扱いになってしまう |
| PBR の過去3・5・10年平均からの離れ方(−1.5σ〜−0.5σ を上に抜けた日) | 毎日買うより悪いものが多く、安定しない |
| PER の過去平均からの離れ方 | 5年平均 −1σ は良かったが、3年・10年では安定せず。固定の20倍のほうが単純で同じくらい良い |

S&P 500 の PBR は自社株買い・IT企業の比重の増加で上がり続けていて(2009年 約1.4倍 → 2026年 約6倍)、日経平均の「PBR 1倍=解散価値」のような目安も無いため、固定の線が働かない。

## データ

- `data/source.json` — `scripts/fetch.py` が書く。手で編集しない
  - `daily`: 日次終値(Cboe の遅延データ `cdn.cboe.com/api/global/delayed_quotes/charts/historical/_SPX.json`、1975年〜)
  - `eps`: 四半期末の EPS(12か月合計、as reported)。multpl.com の月ごとの PER と株価の表から 株価 ÷ PER で出す(multpl の EPS の表は物価調整済みのため)。multpl の EPS の表に載っている四半期まで
  - `bv`: 四半期末の1株純資産(multpl.com、1999年末〜)。S&P の公表が遅く、1年以上前の値になることがある
  - 各四半期の3つ目の値は「使えるようになった日」。期末の3か月後か、実際に初めて取れた日の早いほう。後から分かる値で過去の合図を出さないため
  - 取得した行数が前より減ったときは上書きせず、ワークフローを失敗にする
- `data/analysis.json` — `scripts/analyze.py` が書く分析結果。ページはこれだけを読む
- 作業環境(Claude のクラウド環境)からは multpl・Cboe ともに届かない。Yahoo は Actions からでも 429、stooq は JavaScript の確認画面、FRED は時間切れ、S&P の Excel は 403 だった

## 毎日の更新

`.github/workflows/update-sp500-per.yml` が火〜土 7:30(JST、米国の取引終了後)頃に `fetch.py` → `analyze.py` を実行し、変わっていればコミットして GitHub Pages を再デプロイします。
手で動かすときは、ページの「今すぐ更新」から Issue を作る(所有者が作ると `.github/workflows/request-sp500-per-update.yml` が更新を起動して Issue を閉じる)か、Actions タブ →「S&P500 PER更新」→「Run workflow」。

手元で試すときは、取得元の生データを置いたフォルダを `SP500_RAW_DIR` に指定すると、ネットに出ずに `fetch.py` を動かせます。
